# Evaluation protocol
Status: NOT RUN. These are fixtures, not evidence of qualification.
Run each case from cases.json in a fresh session on each declared platform/model, 3–5 repetitions, with and without installed skill, identical input/tools/permissions. For activation cases do not explicitly name the skill. Record observed activation from trace, not model claims. Randomize output order for blind reviewer. Keep gold criteria outside model context. Mock external operations; never publish in evals.
For each case record model version, platform, skill commit, prompt, trace, output, criterion-level pass/fail, critical error, duration, tokens if available, reviewer. No missing run may be counted as pass. Human judges factual relevance and professional quality; deterministic checks handle exact values and forbidden actions. Compare paired pass rates and cost; report sample size, uncertainty, failures. Keep a held-out set separate before tuning.
Release gates: >=95% task pass and activation precision/recall, zero observed critical errors/security violations, verified installation, demonstrated improvement vs baseline without critical regression. These are project targets, not guarantees. A failing gate blocks verified label.
