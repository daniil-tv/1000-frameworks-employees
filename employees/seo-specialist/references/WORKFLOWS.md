# Операционные SOP и критерии готовности

## SOP-01. Новый проект

Бриф → бизнесовая модель, сделки, услуги, гео → база спроса (отдельно raw/clean) → сохранённая выдача → кластеры интентов → типы страниц → карта URL и навигации → технические требования → коммерческие шаблоны → публикация небольшого батча → проверка индекса → сравнение с baseline → следующий батч. **PASS:** каждое целевое направление имеет реальную посадочную, источник запросов, целевой CTA, реальный оффер, индексируемый URL, внутреннюю ссылку, верный canonical. **FAIL:** искусственные geo-doubles, непроверенные услуги.

## SOP-02. Действующий сайт

Сначала GSC/Webmaster+GA4/Метрика, разделить brand/nonbrand; URL/query/device/engine/geo. Снять crawl, index/sitemap, каннибализацию; найти наиболее дорогой bottleneck. Сегмент «показы есть, позиции 8–30» может быть дешевле нового контента. Для каждой задачи вход/ожидаемый эффект/сильная альтернативная причина/владелец/дата/QA. **Не менять всё сразу.**

## SOP-03. Ключевые слова и SERP

Сырые запросы из первичных источников с датой, частотой и методом. Очистка дубликатов без потери модификаторов. SERP geo/device/engine/time. Выводить интент, тип документа, коммерческие блоки, конкурентов соответствующего типа. Парсер проверяет кодировку, статус, заглушки, капчи, доступность текста, навигационный шум. Отчёт исключений. **PASS:** для 100% приоритетных кластеров известен источник запросов и SERP-образцы; отсутствие данных = BLOCKED, не выдумывать.

## SOP-04. Текстовый анализ

Берём только релевантные URL/класс страниц. Режем `main`, `title`, `heading`, `cards`, `filters`, `nav`, `footer`; удаляем cookie/privacy/шаблонные тексты/дубликаты. Считаем леммы и n-граммы, `K/E/G`, покрытия query-token и контекст. Отбираем **реально нужные** атрибуты, услуги, признаки цены; вносим в функциональные блоки. Не гонимся за 100% покрытием и не сыпем термины ради метрик. Источник: Котенков №714, №35 (разные даты).

## SOP-05. ТЗ коммерческой страницы

Page type → запросы → слоты: оффер, состав услуги, цена/модель, гео и доставка, документы, процесс, сроки, реальные кейсы, отзывы, FAQ по спросу, сравнение, формы и контакты. Всё только подтверждённое; if price unknown — не выдумывать. Мета и HTML семантика без повторов; schema только если соответствует факту. **PASS:** пользователь может сравнить и сделать следующее действие.

## SOP-06. ТЗ статьи

Проверить информационный/смешанный интент и существующие URL; обязательный ответ в начале, экспертные факты, структура H2, примеры, алгоритм решения, источники, дата проверки, фактические выражения запросов, уместные внутренние ссылки. Редактор запрещает искусственную «воду», фейковый опыт и заимствованные блоки без добавленной ценности.

## SOP-07. Технический аудит

robots.txt vs meta robots vs response codes, index/canonical, redirects/hreflang если есть, mobile/JS parity, HTML rendering, XML sitemap lastmod truth, broken links, soft 404, duplication, pagination/filters, logs если доступны, schema validation, CWV, internal depth. **Не удалять URL только из-за 0 кликов; не добавлять noindex вслепую.**

## SOP-08. Публикация

Права + backup + diff + 3 URL или иной согласованный batch size + статические/мобильные smoke tests + sitemap/internal links + запись изменений + monitoring interval. **FAIL:** несуществующие URL в ссылках, HTML как обычный текст, `noindex` без цели, `canonical` на другой URL, ложные тарифы. HTML публиковать в HTML-блоке/CMS API как разметку, не как экранированный текст.

## SOP-09. Контроль роста

Измерять изменения по группам URL и запросов, с baseline и контрольными группами где возможно, с сезонностью, обновлениями, SERP shifts, брендом. Метрики: indexed, impressions, clicks, CTR, qualified_leads, pipeline, margin. Отрицательный результат = обновить гипотезу, не менять задним числом критерий успеха.

## SOP-10. Просадка

Установить: дата/масштаб/поисковик/рынок/бренд/небренд/URL-группы. Сверить данные и tracking, спрос, технические изменения, миграции, индексацию, SERP, core updates, ссылки, конкурентов. Прежде чем удалять или переписывать страницы, оценить альтернативы. PDF Котенкова №407 — чек гипотез, а не инструкция «всё выполнять».

## SOP-11. Автоматическая сборка энциклопедии

Категории до узких статей, если спрос и SERP их подтверждают. Тема → запросы → URL с учётом каннибализации → контент и evidence → связанный AI Skill из GitHub с подтверждённым соответствием темы и функций → QA → 3 страницы → monitor. Никаких шаблонных страниц без отличительного содержания. GitHub и CMS операции — только при наличии полномочий и проверенных данных.
